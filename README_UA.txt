OukitelMonitor v1.6 — оновлення для наявного репозиторію
====================================================
Репозиторій: https://github.com/1796caesar-cmd/OukitelMonitor

У ZIP є 2 файли для репозиторію:
  scripts/update_16.py
  .github/workflows/build-apk.yml

ВАЖЛИВО: не видаляйте інші файли репозиторію.

Як установити оновлення коду через GitHub:
1. Відкрийте свій репозиторій та натисніть клавішу крапки (.) — відкриється github.dev.
2. У папку scripts завантажте файл update_16.py.
3. У папці .github/workflows замініть вміст build-apk.yml файлом з архіву.
4. У вікні Source Control зафіксуйте зміни (Commit) у гілці main.
5. Відкрийте вкладку Actions → Build Android APK → останній запуск.
6. Після успішної збірки відкрийте Artifacts → OukitelMonitor-1.6-APK.

Що змінюється:
* Свайп униз замість кнопки ручного оновлення.
* Налаштування оновлення на екрані від 5 с до 30 хв.
* Фонове оновлення від 5 до 30 хв, незалежний перемикач.
* Кольорові стани: отримано дані, оновлення, помилка, застарілі дані.
* Збереження останнього успішного часу оновлення.
* Залишається графік заряду; графік потужності прибрано.
* Відновлення після тимчасових мережевих помилок без стирання сеансу.
* Пояснення при недійсному токені Wonderfree, повторний вхід.
* versionCode 15 / versionName 1.6.
* Існуюча логіка подій/сповіщень не змінюється.

Обмеження:
* Перед компіляцією код проходить 2 патчі: update_ui_15.py і update_16.py.
* За 0 Вт на вході неможливо достовірно визначити наявність мережі.
  Тому стару логіку PowerMode.kt не змінено, щоб не зламати сповіщення.
* Хмарний сервер може повертати кешовані показники. Зелений стан означає,
  що запит до хмари пройшов успішно, а не гарантований свіжий вимір BMS.
* Готовий APK треба перевірити на телефоні. Локально Android SDK відсутній.
* Якщо підпис debug APK у новій збірці відрізняється, оновлення поверх
  встановленого APK може не вдатися без спільного ключа підпису.
